# 0004 — LangGraph для маршрута, свои проверки для правды

[English](0004-langgraph-over-own-gates.md) · **Русский**

**Статус:** принято (05.11.2026). Дополняет [0001](0001-deterministic-orchestrator.ru.md): порядок
этапов по-прежнему задаёт код, только теперь в виде графа.

**Контекст.** Свой оркестратор (0001) был простым и предсказуемым, но трёх вещей в нём не
было: цикла «ревью → доработка», паузы на подтверждение человеком и продолжения прогона после
падения. Писать это самим — значит заново делать сохранение состояния и маршрутизацию.
Рынок тоже говорит в пользу графа: на hh.ru (03.11.2026) LangGraph упоминается в 159 из
1 233 вакансий со словом LLM (13%), LangChain — в 189 (15%). Остальные фреймворки агентов
встречаются единицами: LlamaIndex 68, CrewAI 24, OpenAI Agents SDK 10, AutoGen 9,
PydanticAI 1.

**Рассмотренные варианты.**

| Вариант | Почему нет |
|---|---|
| Оставить свой оркестратор | цикл, паузу и продолжение пришлось бы писать самим; на рынке РФ не называется |
| LangChain `create_agent` | готовый цикл «модель → инструменты» прячет шаги; контракты этапов пришлось бы встраивать в чужой цикл |
| CrewAI | команды агентов с ролями — не наша задача; нет лимита токенов, отладка непрозрачная |
| OpenAI Agents SDK, PydanticAI | нет сохранения состояния; в вакансиях РФ почти не встречаются |
| LlamaIndex Workflows | сильнее в поиске по документам, чем в оркестрации |

**Решение.** LangGraph задаёт только маршрут: этапы — узлы `StateGraph`, условные переходы
заканчивают ночь раньше, отправляют отчёт на одну доработку и ставят паузу перед публикацией.
Всё, что решает, правда ли отчёт, остаётся обычным кодом вне графа: контракты этапов,
проверки (каждое число — из источника, каждое утверждение — со ссылкой), бюджет, инструменты
только на чтение и публикация. Модель вызывается нашим `HttpLLM`, без `langchain-openai`.
Состояние графа — только JSON, оно сохраняется в SQLite после каждого шага.

**Последствия.**

* Получили цикл доработки (итоговое «accept» в 2 из 3 прогонов против 1 из 3), паузу
  `--approve` и `resume` после падения без повторной оплаты готовых этапов.
* Поведение не изменилось: перенос на граф — 27 из 27 проверок гипотез, те же 66–71 тыс.
  токенов; офлайн-прогон 0,097 с с графом и 0,098 с без него.
* Цена: зависимости `langgraph`, `langchain-core`, `langsmith` и SQLite-checkpointer
  (`uv.lock` вырос примерно на тысячу строк); узел после продолжения выполняется с начала,
  поэтому до `interrupt()` нет побочных эффектов.
* Сохранение — это точки сохранения, а не гарантия завершения: упавший прогон сам не
  перезапустится, его продолжают командой `overnight resume`.
* Если понадобится отказаться от LangGraph, узлы — обычные функции с нашими контрактами,
  их можно вызвать в цикле, как было в 0001.
