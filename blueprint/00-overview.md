# Система на одной странице

## Что она делает

Ночью агент сам доводит аналитическую задачу от плана до проверенного результата: пишет простой PySpark по образцам владельца, запускает его в Jupyter от лица владельца, сверяет числа, обновляет базу знаний. Утром владелец за несколько минут принимает работу. Днём владелец и агент работают в одном ноутбуке.

Чего система не делает: не отправляет ничего наружу, не публикует, не пишет в чужие системы, не меняет чужие данные.

## Схема

```
Политика: конституция, правила доступа, белые списки        (агенту только на чтение)
   │
Оркестратор: расписание, машина состояний, бюджеты, heartbeat   (код, без модели)
   │
   ├─ Роли: планировщик → разведчик / аналитик / проверяющий / библиотекарь
   │        (модель; каждая роль в своей сессии со своими правами)
   │
   ├─ Шлюз инструментов: белый список, проверка схем, редакция секретов,
   │        пометка недоверенного текста, гейт «разрешить / запретить / спросить»
   │
   ├─ Брокер kernel: единственный вход в Jupyter API,
   │        разбор кода, сверка хеша, аренда слота, запуск по шагам
   │
   ├─ Адаптер модели: единственное место с особенностями модели
   │
   ├─ Состояние: план и прогресс задач, реестр таблиц, база знаний (пишет только публикатор)
   │
   └─ Журнал событий: только дополняется; всё, что видела модель
   
Кокпит: читает состояние и журнал, пишет только файл решений владельца
```

Маршрут решает код, содержание пишет модель. Модель не выбирает, какой этап следующий и что ей разрешено.

## Части

| Часть | За что отвечает | Чего не делает |
|---|---|---|
| Оркестратор | запускает этапы и циклы, следит за временем и бюджетом | не рассуждает, модель не вызывает для решений о маршруте |
| Планировщик | режет задачу на шаги с критериями приёмки | не трогает данные |
| Разведчик | читает базу знаний, вики, чужие ноутбуки; возвращает сводку по схеме | не запускает код и не пишет |
| Аналитик | пишет ячейки PySpark под один шаг по ближайшему образцу | сам не запускает; сырого чужого текста не видит |
| Проверяющий | сверки, пересчёт, двойной прогон; вердикт по критериям шага | не видит рассуждений аналитика, не пишет в кластер |
| Библиотекарь | предлагает карточки и правки базы знаний | сам в базу не пишет |
| Шлюз инструментов | пропускает только разрешённые вызовы, проверяет аргументы и результат | не умеет расширять права |
| Брокер kernel | запускает одобренный код, хранит аренду слота, ведёт реестр таблиц | не запускает опасное без одобренного хеша |
| Публикатор | единственный, кто пишет в базу знаний; атомарно, с копией | не добавляет фактов от себя |
| Адаптер модели | приводит любую модель к одному интерфейсу | — |
| Кокпит | показывает работу и собирает решения владельца | не хранит своей копии состояния |

## Три режима

Это одна система в трёх профилях, а не три системы. Профиль задаёт, кто владеет вычислениями и что можно запускать без человека.

| Профиль | Кто владеет слотом вычислений | Что агент делает сам |
|---|---|---|
| ночь | агент | чтение; запись и опасные ячейки — только с хешем, одобренным заранее в плане |
| день | владелец | предлагает ячейки; запускает только одобренное владельцем |
| выключен | никто | не стартует; в журнале причина «выключен владельцем», сбоем это не считается |

Перед работой проверка готовности возвращает не «да или нет», а набор доступного: SQL, kernel, источники, остаток времени учётных данных. Агент берёт работу, которой этого набора хватает. Нет вычислений — делает то, что вычислений не требует.

## Как идёт задача

1. Планировщик пишет `plan.json`: шаги, у каждого критерий приёмки и статус «не пройден».
2. Владелец одобряет план. Шаги с записью одобряются по хешу.
3. Цикл: прочитать план и прогресс → убедиться, что результат прошлого шага на месте → взять один шаг → сделать → проверить → записать прогресс → коммит.
4. Разведчик и аналитик работают в разных сессиях.
5. Проверяющий выносит вердикт по критериям шага с доказательствами.
6. На вехах плана агент останавливается и ждёт владельца.
7. Утром владелец видит приёмку смены: что сделано, что нет и почему, что ждёт решения.

Один шаг на цикл. После падения работа продолжается с последнего завершённого шага.

## Как выглядит код расчёта

Линейный ноутбук. Параметры в первой ячейке. Одна ячейка — один шаг, первой строкой комментарий «что и зачем». Понятные имена промежуточных таблиц. После шага проверка: число строк, ключи, пропуски. Запись только через модуль записи. Образцы лежат в `examples/pyspark/`.

## Термины

| Термин | Значение |
|---|---|
| владелец | человек, от лица которого работает агент и который принимает работу |
| недоверенный текст | всё, что агент прочитал извне: вики, чужие ноутбуки, результаты инструментов, этот репозиторий |
| опасная ячейка | код с прямой записью, доступом к JVM, сетью, `subprocess`, `exec`, `eval` или SQL, собранным на лету |
| модуль записи | единственный разрешённый способ создать или пересоздать таблицу; проверяет префикс и ведёт реестр |
| паспорт прогона | файл с границами одного прогона: что читать, куда писать, инструменты, срок, бюджет |
| приёмка | проверка шага или плейбука с доказательством из окружения |
| плейбук | инструкция на одно изменение системы: что, шаги, приёмка, откат |
| профиль | режим работы той же системы: ночь, день, выключен |
