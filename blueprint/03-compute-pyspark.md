# Вычисления и код на PySpark

Как агент пишет и запускает расчёты. Главное требование: владелец должен прочитать код агента и поменять его сам, без агента. Поэтому простота здесь — правило, а не пожелание (К7).

## Откуда берётся код

Агент не пишет расчёт с нуля. Он находит ближайший образец из скриптов владельца и переделывает его под задачу.

1. По задаче определи, что нужно: какие данные, какое преобразование, что на выходе.
2. Найди карточку образца в базе знаний (тип записи «образец»). У карточки: что делает скрипт, вход, выход, какие приёмы использует.
3. Открой сам скрипт. Возьми из него приёмы, порядок шагов, стиль.
4. Если образца нет — напиши `НУЖНО УТОЧНИТЬ: нет образца для <что нужно>` и предложи владельцу план на словах.

Обобщённые образцы лежат в `examples/pyspark/`. Скрипты владельца лежат только в его окружении.

## Как устроен ноутбук

Ноутбук читается сверху вниз и выполняется сверху вниз. Никаких переходов назад.

```python
# Шаг 0. Параметры: период и имена таблиц. Меняются только здесь.
from pyspark.sql import functions as F, Window

DATE_FROM = "2026-10-01"
DATE_TO = "2026-10-31"
SRC_RESPONSES = "<СХЕМА>.<ТАБЛИЦА_ОТКЛИКОВ>"
OUT_TABLE = "<РАБОЧАЯ_СХЕМА>.<ПРЕФИКС_АГЕНТА>_responses_oct"
```

```python
# Шаг 1. Отклики за период: берём только нужные поля.
responses = (
    spark.table(SRC_RESPONSES)
    .where(F.col("response_date").between(DATE_FROM, DATE_TO))
    .select("response_id", "client_id", "campaign_id", "response_date")
)

# Проверка шага: есть строки, нет пустых ключей.
print("строк:", responses.count())
print("пустых client_id:", responses.where(F.col("client_id").isNull()).count())
```

```python
# Шаг 2. Убираем повторные отклики: оставляем первый по дате.
# response_id в сортировке — чтобы при одинаковой дате результат был одинаковым при каждом запуске.
w = Window.partitionBy("client_id", "campaign_id").orderBy("response_date", "response_id")
first_responses = (
    responses
    .withColumn("rn", F.row_number().over(w))
    .where("rn = 1")
    .drop("rn")
)

print("строк до:", responses.count(), "после:", first_responses.count())
```

```python
# Шаг 3. Сохраняем результат через модуль записи.
save_table(first_responses, OUT_TABLE)
```

## Правила простого кода

| Правило | Почему |
|---|---|
| Первая ячейка — параметры: даты, имена таблиц, пороги | владелец меняет расчёт в одном месте |
| Одна ячейка — один шаг. Первая строка — комментарий «Шаг N. Что и зачем» | ноутбук читается как план |
| После каждого шага — проверка: число строк, пустые ключи, дубли | ошибка видна на том шаге, где возникла |
| Понятные имена промежуточных DataFrame: `first_responses`, а не `df2` | код читается без пояснений |
| Цепочка вызовов — не длиннее 6–7 методов; длиннее — разбей на два шага | длинную цепочку трудно проверить |
| Без классов, декораторов, вложенных функций, метапрограммирования | владелец не должен разбираться в абстракциях |
| Функция — только если нужна минимум дважды | одноразовая функция только прячет код |
| Только библиотеки и приёмы, которые есть в образцах владельца | никаких новых зависимостей |
| Ячейка до ~30 строк, вложенность до 3 | больше — значит шаг надо делить |
| Окна с детерминированным порядком: в `orderBy` есть уникальный ключ, которого нет в `partitionBy` | повторный запуск даёт тот же результат |
| Без «защиты на будущее»: обработка ошибок, которая их прячет, заготовки под другие случаи | лишний код без пользы |

Пороги (30 строк, 6–7 методов) проверяет гейт сложности. Ячейка, которая его не проходит, возвращается с сообщением, что упростить.

Перед тем как отдать код, проверь себя вопросом: владелец прочитает и поменяет эту ячейку за пять минут? Если нет — упрости.

## Чтение и запись

| Класс | Что входит | Правило |
|---|---|---|
| чтение | `spark.table`, `spark.read`, SELECT, преобразования DataFrame, `count`, `show` | можно всегда, в пределах лимитов паспорта |
| запись в своё | создание и пересоздание таблиц с префиксом агента через модуль записи | только в шаге плана, одобренного владельцем (К4, К19) |
| всё остальное | запись вне префикса, удаление чужого, ALTER, GRANT, прямой доступ к JVM и файловой системе кластера | нельзя никогда |

Модуль записи — единственный способ записать таблицу:

| Функция | Что делает |
|---|---|
| `save_table(df, name)` | создаёт таблицу; падает, если имя без префикса агента или не в рабочей схеме; вносит имя в реестр задания |
| `recreate_table(df, name)` | пересоздаёт таблицу; можно только для имени из реестра этого задания |
| `drop_table(name)` | удаляет таблицу; можно только для имени из реестра этого задания |

Как устроен модуль внутри, решает владелец под своё окружение. Агент его не меняет (К11).

## Что считается опасным и что писать вместо

Брокер разбирает каждую ячейку до запуска. Если находит опасное, ячейка не запускается, а агент получает сообщение, что писать вместо.

| Что нашёл разбор | Что писать вместо |
|---|---|
| `df.write...`, `saveAsTable`, `insertInto` | `save_table(df, name)` |
| `spark.sql(...)` с CREATE, INSERT, DROP, ALTER | `save_table`, `recreate_table` или `drop_table` |
| `spark.sql(f"...")` или строка, собранная из переменных | DataFrame API; литерал SQL только для чтения |
| `spark._jvm`, `spark._jsc`, обращение к файловой системе кластера | нельзя; если нужно — `НУЖНО УТОЧНИТЬ` |
| `subprocess`, `os.system`, сетевые библиотеки | нельзя |
| `exec`, `eval`, `importlib` | нельзя |
| импорт библиотеки, которой нет в образцах | взять приём из образцов или `НУЖНО УТОЧНИТЬ` |

Разбор кода — не песочница: Python позволяет обойти любую статическую проверку. Поэтому настоящая граница двойная: одобрение по хешу (К6) и права владельца в кластере.

## Как идёт запуск

1. Аналитик пишет ячейки под один шаг плана.
2. Гейт сложности и разбор кода проверяют их; затем ревьюер кода (`agents/code-reviewer.md`).
3. Ячейки только на чтение брокер запускает сам. Записывающие — только если их хеш совпадает с одобренным в плане.
4. После запуска проверка шага: числа из вывода сравниваются с ожиданием из плана.
5. Расчёт дольше лимита запускается фоном; брокер опрашивает статус и пишет heartbeat. После падения работа продолжается с последнего завершённого шага.

## Слот вычислений
