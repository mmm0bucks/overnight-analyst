# База знаний и поиск

Что агент хранит между прогонами, как туда попадает новое и как агент находит нужное.

## Что в базе

| Тип записи | Что в ней |
|---|---|
| сущность | таблица, поле, метрика, термин, процесс, домен: что это и как использовать |
| образец | скрипт владельца: что делает, вход, выход, какие приёмы |
| решение | что решили по задаче и почему |
| гипотеза | предположение, статус (новая, подтверждена, опровергнута, частично), доказательства |
| противоречие | два источника говорят разное; оба источника и что проверить |
| разбор задачи | суть задачи, что сделано, что осталось |

## Формат записи

```markdown
---
id: metric-first-response        # стабильный, не меняется
type: сущность
name: Первый отклик
trust: расчёт                     # уровень доверия, см. ниже
sources:
  - расчёт, задача <ключ>, 2026-11-12
  - вики, страница <тип страницы>, 2026-10-30
status: активна                   # активна | устарела | противоречие
checked: 2026-11-12               # когда последний раз проверено
updated: 2026-11-12
---
Первый по дате отклик клиента на кампанию. Повторные отклики не считаются.

## Как получить
<короткое описание или ссылка на образец>

## Оговорки
<что легко перепутать>
```

## Уровни доверия

От большего к меньшему:

| Уровень | Откуда |
|---|---|
| владелец | владелец сказал или подтвердил |
| расчёт | агент проверил на данных, есть запрос и результат |
| документ | вики, описание витрины, официальная методика |
| чужой код | вывод из чужого ноутбука или скрипта |
| веб | результат корпоративного веб-поиска по открытым источникам |

## Как факт попадает в базу

Агент не пишет в базу сам. Он предлагает факт с источником, публикатор решает (К18).

1. **Найти похожее.** Публикатор ищет записи с тем же `id`, именем или смыслом.
2. **Такое уже есть** — к записи добавляется источник и дата. Новая запись не создаётся.
3. **Противоречит** — запись не меняется. Создаётся запись «противоречие» с обоими источниками и тем, что проверить. Она попадает в утренний отчёт.
4. **Новое** — проверяется критерий важности. Прошло — запись создаётся. Нет — факт отбрасывается.
5. Факт с меньшим доверием не заменяет и не ослабляет запись с большим доверием. Если источник с большим доверием подтверждает запись, её `trust` повышается.

## Критерий важности

Факт записывается, если выполняется хотя бы одно:

- пригодится в другой задаче, а не только в этой;
- без него агент уже ошибался или может ошибиться;
- это решение владельца или итог расчёта;
- это неочевидная оговорка: как правильно соединять, что легко перепутать, где данные врут.

Не записывается:

- то, что легко найти заново за один запрос;
- промежуточные числа, которые нужны только внутри задачи;
- пересказ страницы вики без вывода;
- факт, который нельзя проверить и который ни на что не влияет.

## Устаревание

Запись, которую не подтверждали дольше срока из конфига, получает статус «устарела». Агент может её читать, но не опирается на неё без проверки. Удаляет записи только владелец.

## Поиск

Порядок, от точного к примерному:

1. **Точный поиск** по `id`, имени, коду, ключу задачи, имени таблицы. Коды и идентификаторы ищутся только так: смысловой поиск их путает.
2. **Поиск по словам** (BM25).
3. **Смысловой поиск** по эмбеддингам.

Результаты 2 и 3 сливаются (RRF). Перед эмбеддингом к тексту куска приклеивается заголовок записи и её тип.

Правила выдачи:
- Есть порог похожести. Ниже порога — ответ «не найдено», а не три случайных куска.
- Короткая запись отдаётся целиком, длинная — кусок со ссылкой на запись.
- Найденное — навигация, а не доказательство. Число из базы перед использованием проверяется по первоисточнику.
- Индекс пересчитывается только для изменившихся записей.

## Проверочный набор

В базе знаний лежит набор пар «запрос → нужная запись»: точные коды, «что решили по задаче», методики, запросы без ответа. После каждого изменения поиска набор прогоняется, считаются попадание в первую тройку и доля честных «не найдено». Изменение без замера «до и после» не принимается.
