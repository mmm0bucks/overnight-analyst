# Роли и субагенты

Задачи у ночного агента бывают любыми, поэтому роли не привязаны к типам задач. Есть небольшой набор ролей с узкими правами. Ведущий для каждой задачи сам решает, кого и сколько раз вызвать. Несколько обязательных вызовов задаёт код, а не ведущий.

## Набор ролей

| Роль | Файл | Что делает | Чужой текст | Kernel | Пишет |
|---|---|---|---|---|---|
| ведущий | `agents/lead.md` | ведёт задачу: план, вызов ролей, сборка итога | нет, только сводки по схеме | нет | план, прогресс, черновик отчёта |
| разведчик | `agents/scout.md` | ищет и читает внутри: база знаний, вики, трекер, чужие ноутбуки | да | нет | ничего |
| веб-разведчик | `agents/web-scout.md` | ищет в открытых источниках через корпоративный веб-поиск по общему вопросу | да | нет | ничего |
| аналитик | `agents/analyst.md` | пишет ячейки PySpark под один шаг по образцу владельца | нет | чтение; запись только по одобренному хешу | ячейки в ноутбук задачи |
| ревьюер кода | `agents/code-reviewer.md` | проверяет ячейки: простота, соответствие плану, опасное | нет | нет | ничего |
| проверяющий | `agents/verifier.md` | независимо пересчитывает числа своим кодом и сверяет | нет | только чтение | ничего |
| библиотекарь | `agents/librarian.md` | предлагает факты для базы знаний с источником | нет, только сводки по схеме | нет | предложения для публикатора |

Набор задаётся файлами в `agents/`. Добавить роль — добавить файл и строку в эту таблицу; права новой роли не могут быть шире, чем у существующей роли с тем же доступом.

## Сколько ролей вызывать

Больше ролей — больше расход и больше мест для ошибки. Ведущий подбирает состав под сложность задачи:

| Задача | Состав |
|---|---|
| простая: один расчёт по готовому образцу | аналитик, ревьюер кода, проверяющий |
| нужно разобраться: методика, источники, как делали раньше | плюс 1–3 разведчика с разными вопросами |
| сложная: несколько независимых частей | части по очереди, разведчики параллельно; на каждую часть свой цикл «аналитик — ревьюер — проверяющий» |

Нельзя: запускать разведчиков на простой вопрос, на который отвечает одна запись в базе знаний; давать двум разведчикам один и тот же вопрос.

Сама система ролей вводится постепенно и с замером: сначала один агент с проверяющим, затем роли по одной, и каждая остаётся, только если оценка на проверочных задачах стала лучше. Без замера роль не добавляется.

## Кто кого вызывает

- Вызывает только ведущий. Субагент не вызывает субагентов: глубина одна.
- Остановить субагента может владелец или ведущий. Субагенты не общаются между собой: всё идёт через ведущего.
- Ведущий выбирает роли под задачу. Простой задаче может хватить аналитика и проверяющего; задаче «разобраться в методике» — нескольких разведчиков.
- Обязательные вызовы проверяет код, ведущий их не отменяет:

| Перед чем | Кто обязателен |
|---|---|
| ячейка попадает в итоговый ноутбук | гейт сложности (код), затем ревьюер кода |
| шаг с записью в кластер | ревьюер кода и проверяющий; запуск только с одобренным хешем |
| шаг отмечается «пройден» | проверяющий |
| факт уходит в базу знаний | библиотекарь, затем публикатор (код) |

## Разделение по чужому тексту (К9)

Чужой текст читают только разведчики. Их сессии помечены «читала недоверенное», и в них нет kernel и записи.

Разведчиков два, чтобы ни в одной сессии не сошлись три вещи сразу: чужой текст, внутренние данные и выход наружу.

| Сессия | Чужой текст | Внутренние данные | Выход наружу |
|---|---|---|---|
| разведчик | да | да, только чтение | нет |
| веб-разведчик | да | нет: получает только общий вопрос от ведущего | да, веб-поиск |
| аналитик, проверяющий | нет: только сводки по схеме | да | нет |

Ведущий формулирует вопрос веб-разведчику сам, общими словами, без имён таблиц, полей, чисел и текста задач. Шлюз проверяет вопрос так же, как поисковый запрос (К1).

Разведчик возвращает ответ строго по схеме. Код проверяет схему, а значения, которые пойдут в код (имена таблиц, полей, периоды), сверяет с каталогом. Дальше передаётся только проверенный ответ. Сырой текст вики, чужих ноутбуков и веба к ведущему, аналитику и проверяющему не попадает.

Если аналитику нужен приём из чужого ноутбука, разведчик пересказывает приём словами по схеме, а не копирует код.

## Задание субагенту

Ведущий даёт задание из четырёх частей. Расплывчатое задание даёт дубли и пропуски.

```
Цель: <что нужно получить, одной фразой>
Ответ: <схема ответа роли из её файла>
Можно: <какие источники и инструменты; не шире прав роли>
Границы: <чего не делать; лимит шагов и времени>
```

Пример задания разведчику:

```
Цель: найти, как в методике считается первый отклик на кампанию.
Ответ: схема scout_result.
Можно: база знаний, вики, ноутбуки из папки задач владельца.
Границы: не больше 20 шагов; код не копировать, приём описать словами.
```

## Ответ субагента

У каждой роли своя схема ответа, она указана в файле роли. Общие поля у всех:

```json
{
  "role": "scout",
  "stop": "completed",
  "summary": "одна-две фразы",
  "sources": ["тип источника: что именно"],
  "need_owner": []
}
```

`stop` — причина остановки:

| Значение | Когда |
|---|---|
| `completed` | задание выполнено |
| `completed_with_concerns` | выполнено, но есть сомнения; они в `summary` |
| `need_clarification` | не хватает данных или инструкции; вопрос в `need_owner` |
| `blocked_by_rule` | мешает правило конституции; номер правила в `need_owner` |
| `limit` | кончился лимит шагов или времени |
| `error` | сбой инструмента или окружения |

Ответ, который не проходит схему, считается `error`. Ведущий может повторить задание один раз.

Ответ короткий: выжимка, а не пересказ всего прочитанного. Ориентир — до 1,5 тысяч токенов. Подробности остаются в журнале сессии субагента.

Цикл «ревьюер вернул — аналитик исправил» идёт не больше двух кругов. Не сошлось — шаг останавливается, причина в отчёт.

## Параллельность

Ночью (18:00–09:00) токены не ограничены и разрешено много одновременных запросов. Поэтому:

- разведчиков, ревьюеров и библиотекаря можно запускать параллельно, сколько нужно;
- kernel один: всё, что запускает код, идёт через брокер в очередь. Аналитик и проверяющий параллельно готовят код, но запускаются по одному;
- проверяющий не видит ни рассуждений аналитика, ни его кода: только план шага и артефакты. Иначе он повторит ту же ошибку.

Неограниченные токены не отменяют лимитов шагов: они ловят зацикливание. Лимиты указаны в файлах ролей.

## Как это ложится на харнесс

Файлы `agents/` написаны без привязки к харнессу. Сборщик переносит их в механизм своего харнесса: описание агента-субагента, его набор инструментов и права. Поля файла роли:

| Поле | Что значит |
|---|---|
| `name` | имя роли |
| `description` | что делает и когда вызывать; по нему ведущий выбирает роль |
| `untrusted_input` | читает ли чужой текст; если да — сессия помечается |
| `kernel` | `none`, `read` или `read_write_by_hash` |
| `tools` | белый список инструментов по категориям |
| `writes` | куда может писать |
| `max_steps`, `max_minutes` | лимиты против зацикливания |
| `profile` | профиль модели из адаптера: `low` для простых ролей, `high` для тех, где ошибка дорогая; модель не называется |
| `output` | имя схемы ответа |

Если харнесс не умеет запретить роли инструмент, запрет ставится в шлюзе инструментов по имени роли. Инструкция в тексте роли защитой не считается.
