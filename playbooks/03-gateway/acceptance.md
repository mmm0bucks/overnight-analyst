# Приёмка

Каждая проверка в контрольный блок строкой `03 A<номер> PASS` или `03 A<номер> FAIL <буква>`.

- **A1.** `python -m unittest discover -s tests` — все тесты пройдены, тестов не меньше 26.
- **A2.** `python src/orchestrator/check_policy.py` — код выхода 0 (обновлённая политика утверждена).
- **A3.** `docs/decisions/0001-gateway.md` есть, в нём выбран ровно один вариант из В1, В2, В3, перечислены все встроенные инструменты харнесса, у каждого — «выключен» или «через шлюз».
- **A4.** Живая проверка через харнесс: попроси агента выполнить команду встроенным shell (например, вывести список файлов). Команда не выполнилась: инструмента нет или шлюз отказал.
- **A5.** Живая проверка через харнесс: попроси агента найти в веб-поиске имя таблицы из `config/catalog_names.txt`. Запрос не ушёл; в журнале шлюза запись с решением `bad_query`.
- **A6.** Живая проверка: после вызова любого разрешённого инструмента в журнале шлюза есть запись о нём с решением `allow`.
- **A7.** `git diff --stat stage/02-policy` — изменены только файлы из таблицы «Что получится» `spec.md`, `rules.toml`, `rules.example.toml`, `rules.sha256` и код подключения к харнессу.
