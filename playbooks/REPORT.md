# Отчёт по плейбуку

Заполняет агент после прохождения приёмки. Полный отчёт остаётся у владельца, в его окружении. Наружу владелец выносит только контрольный блок.

Правила те же, что в аудите: без ключей, адресов, имён людей, названий систем, таблиц, схем и путей; без цитат кода и промптов. Сомневаешься — пиши `не раскрываю`.

```
# Отчёт: плейбук <номер и имя>

Версия инструкции: <тег или коммит репозитория, по которому работал>
Ветка git в моей системе: <имя ветки>
Итог: выполнен / выполнен частично / не выполнен

## Что изменено
- <часть системы>: <что было> → <что стало>

## Приёмка
Для каждой проверки из acceptance.md одна строка:
- <проверка>: пройдена / не пройдена — <доказательство: вывод команды, результат теста, число>

## Отклонения от плана
- <что сделано иначе, чем в plan.md, и почему>
(если отклонений нет, написать «нет»)

## Что не получилось и почему
- <шаг>: <причина>; <номер правила конституции, если упёрся в него>

## Вопросы
- НУЖНО УТОЧНИТЬ: <вопрос>

## Как откатить
<команда или шаги; проверено ли, что откат работает>

## Цифры
Тестов до / после: <N> / <N>. Токенов потрачено: <N>. Время: <минут>.
```

После отчёта агент останавливается. Вливает изменение владелец, после просмотра diff.

## Контрольный блок

Последним в ответе агент печатает контрольный блок. Это единственное, что владелец может вынести из своего окружения, поэтому формат строгий и закрытый: никакого свободного текста, путей, чисел, названий.

```
CHECK <имя блока или плейбука> <коммит шаблона, первые 7 символов>
<плейбук> A<номер> PASS
<плейбук> A<номер> FAIL <буква>
```

Буква причины — одна из четырёх:

| Буква | Причина |
|---|---|
| N | нет файла, команды или доступа |
| E | команда выполнилась с ошибкой |
| U | не хватило инструкции, «нужно уточнить» |
| R | мешает правило конституции |

Пример:

```
CHECK A 72c23ff
01a A1 PASS
01a A2 PASS
02 A1 PASS
02 A3 FAIL E
```

Проверку, до которой не дошли, не печатай: отсутствие строки само говорит, где остановились.
