# Плейбук 02. Политика и проверка при старте

## Что это

Политика — это файл правил: какой роли какое действие можно, нельзя или можно только с одобрением владельца. Здесь появляются сам файл правил, модуль, который по нему решает, и проверка, без которой агент не запускается.

## Зачем

- Новое действие закрыто, пока его явно не разрешили (первое правило запрещает всё).
- Есть запреты, которые не открываются ничем: запись в трекер и вики, установка пакетов, push, правка своих ограничений, запуск кода после чтения чужого текста (К2, К3, К9, К11).
- Если файл правил пропал, сломан или изменён без владельца, агент не стартует (угроза «защита тихо выключена»).

На этом этапе политика ещё ни к чему не подключена: это делает шлюз на этапе 3. Здесь проверяется, что сама политика решает правильно.

## Что получится

| Файл | Что это |
|---|---|
| `config/policy/rules.toml` | правила, по образцу |
| `config/policy/rules.example.toml` | образец без изменений, для сравнения |
| `config/policy/rules.sha256` | хеш правил, утверждённых владельцем |
| `src/gateway/policy.py` | решение: allow, ask, queue или deny |
| `src/orchestrator/check_policy.py` | проверка при старте и утверждение владельцем |
| `tests/test_policy.py` | 14 тестов |

## Правила

1. Образцы из `examples/policy/` копируются без изменений. Хочется изменить — `НУЖНО УТОЧНИТЬ`, не меняй сам.
2. Нужен Python 3.11 или новее: модуль читает правила стандартной библиотекой (`tomllib`). Сторонних пакетов не нужно, и ставить их нельзя.
3. Утверждает политику только владелец. Сборщик не запускает `--approve` сам.
